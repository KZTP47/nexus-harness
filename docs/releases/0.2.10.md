# Nexus Harness 0.2.10

This release improves chat responsiveness and attachment handling, makes task
completion visible, and requires stronger evidence for executable deliverables.

- Load signed histories with one integrity-key read per verification pass and
  avoid rewriting unchanged compatibility snapshots. Reuse route and project
  checks within each chat-list request while keeping later reads and admission
  checks fresh.
- Keep a second saved chat usable while another goal runs. Separate project
  folders can run concurrently; overlapping folders retain their project queue.
- Show completed goals in a distinct Nexus Harness icon bubble with a link to
  result and verification details, retained through history reloads.
- Put pasted files and images in the same attachment tray as picker-selected
  files. Preserve exact-chat ownership during asynchronous reads, removal and
  sending; keep normal text paste intact.
- Require executed checks for apps, games and scripts. Missing tests trigger a
  bounded repair task to author meaningful checks, rather than completion from
  file existence and contributor agreement. Document and read-only work retain
  their appropriate evidence requirements.
- Explain the supported contained browser verification path to agents and
  require critical review of actual behavior and launch conditions. HTTP-route
  checks do not establish that an ES-module page works when opened as a file.

Existing command approval, file boundaries, integrity verification, exact
provider/chat identity, cancellation, budgets and recovery remain enforced.
The versioned verification policy applies to new and incomplete resumed goals;
historical completed goals are not rewritten or retroactively certified.
