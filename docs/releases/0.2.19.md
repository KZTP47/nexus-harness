# Nexus Harness 0.2.19

A failure to launch the protected Playwright browser or exact-origin proxy
could leave a Python exception object inside a verification result. Saving
that result then failed with "Object of type OSError is not JSON serializable",
hiding the original cause and interrupting the team's verification turn.

- Browser, proxy, runner and cleanup launch failures now produce JSON-safe
  process results retaining the original diagnostic, exception type and native
  error codes. Failure reports can be saved and read after restart.
- Both static browser probes and unmodified Playwright suites report protected
  runtime failures as verification unavailable. A suite that never launched is
  no longer described as executed. Actual project assertion failures remain
  failed checks, and all existing containment requirements remain enforced.
- A failed run does not poison subsequent attempts. Restart Nexus Harness and
  use Resume team to retry a paused goal with the updated runtime.

Verified locally with 55 passing focused tests and one optional live-suite
skip, plus a real protected-browser check. The original serialization failure
was reproduced with injected native launch errors. The historical launch
condition itself did not recur during the real-browser check.

Published from isolated source with unrelated local work excluded, without
waiting for GitHub CI. The Windows installer is unsigned; its accompanying
SHA-256 file verifies the download bytes.
