# Nexus Harness 0.2.27

The email assistant adds mailbox connection choices, reviewed replies, persisted
drafts and recipient-scoped writing preferences. Automatic revision learning
shows successful, empty and failed outcomes and supports guarded retries.
Recurring template corrections preserve paired omissions and replacements.
Polling settings persist, scans do not overlap, and browser checks prioritize
changed conversations. See [Email assistant](../email-assistant.md) for adapter
capabilities and provider setup requirements.

Facilitator mode supports direct project work with serialized participants,
explicit access choices and recovery of earlier private work. Chat input remains
editable while saved-chat and provider requests are pending. Chat and
collaboration settings have separate views.
Pending request recovery verifies the originally saved permissions and work mode,
including older records, even when current chat preferences have changed.

Publication cleanup removes private mailbox/session observations from development
documentation. Classic Outlook resolves the configured Windows system directory
instead of assuming a drive. Packaged source excludes local account state and
Python bytecode caches; test mail uses synthetic addresses. New and existing
projects automatically ignore private email databases, browser profiles and
mail-engine state before the email assistant creates its storage.

API mailbox sign-in still requires legitimate publisher registrations. Browser
reading supports bounded rendered conversations and needs the app running;
classic Outlook exports approved replies. Real provider delivery and prolonged
unattended operation are separate integration acceptance boundaries.

This Windows build is unsigned. The release includes its SHA-256 and offline
installation bundle; the release workflow reports measured installation size.
