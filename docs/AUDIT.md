# Source Binding Audit

Audit date: 2026-08-14.

The source harness was inspected read-only. The new package was written in a separate destination. No source file was copied into the package.

## Decoupling rule

The `our_harness` core must not contain source-project names, user paths, drive letters, fixed branches, fixed remotes, named build outputs, or fixed documentation paths. `harness audit` enforces this over executable source, templates, examples, and installers. This audit note is excluded because it records the removed bindings. The packagers copy from the working tree, not from Git: `scripts/build_zipapp.py` copies `src` minus `__pycache__`, `*.pyc`/`*.pyo`, `*.egg-info`, `build` and `dist`, and electron-builder copies `desktop/package.json`'s `build.files` and every `extraResources` source (`src`, `scripts/harness.py`, `THIRD_PARTY_NOTICES.md`) through that entry's `filter`. The audit reads the same manifest and filters. In a Git checkout it therefore skips Git-ignored files only where no packager copies them (a scratch clone at the repository root, local caches, a per-machine `src/*.egg-info`). An ignored file that a packager does copy, such as a local `.env` under `src`, would ship: it is still scanned and is also reported as "ignored file would ship". `desktop/build-info.json` is generated by the release build and shipped by design, so it is scanned but not reported as ignored. When Git cannot say what is ignored, nothing is skipped.

Project policies belong in entry-point plugins or explicitly enabled project-relative plugin files. Loading a plugin is an execution decision; a discovered file is never loaded automatically.
